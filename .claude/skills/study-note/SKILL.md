# Study Note 초안 작성

## 목적

VibeCording Master 앱의 각 학습 항목은 지금 제목만 있고 본문 설명이 없다.
대표가 항목을 하나씩 골라 AI와 대화하며 그 개념을 공부하고,
최종적으로 만족하는 설명만 골라서 그 항목의 "메모"칸에 직접 저장하도록 돕는다.

AI가 만든 초안을 그대로 자동 저장하지 않는다.
대표가 대화로 다듬고 확정한 내용만 최종본으로 제시한다.

## 절차

### 1. 대상 항목 파악

대표가 항목 id(`js/data.js`의 `id`, 예: `ai-3`) 또는 항목 제목을 알려주면
`js/data.js`에서 해당 subtopic을 찾는다.

찾을 때 함께 확인할 것:
- 그 항목이 속한 topic의 `name`, `sub`, `desc` (전체 맥락)
- 같은 topic 안의 앞뒤 항목들 (학습 흐름상 순서, 무엇을 배운 다음이고 무엇으로 이어지는지)

항목을 못 찾으면 추측하지 말고 대표에게 정확한 항목을 다시 확인한다.

### 2. 설명 초안 작성

다음을 포함해 이해하기 쉬운 한국어로 초안을 작성한다.

- **개념**: 이 항목이 무엇인지, 한두 문장으로 먼저 명확히
- **왜 필요한가**: 바이브코딩(AI와 함께 개발하기) 맥락에서 이게 왜 중요한지
- **전체 흐름 속 위치**: 같은 섹션의 앞/뒤 항목과 어떻게 연결되는지
- **실전 관점**: 실제로 어떻게 쓰이는지, 흔한 실수나 주의점이 있다면 함께

전문 용어를 쓸 때는 처음 등장할 때 짧게 풀어준다.
과도하게 길게 쓰지 않는다 — 메모칸에 붙여넣고 읽을 분량을 고려한다.

### 3. 대화로 다듬기

초안을 보여준 뒤 대표의 반응을 기다린다.
"더 짧게", "예시 추가", "이 부분 더 자세히", "이해 안 됨" 같은 피드백을 받으면
그 부분만 다시 작성한다. 여러 라운드가 정상이다 — 한 번에 끝내려 하지 않는다.

### 4. 최종본 전달

대표가 "이걸로 저장", "확정", "됐다" 같은 신호를 주면:

1. 최종 텍스트를 복사하기 쉬운 형태로 깔끔하게 제시한다.
2. 다음 안내를 함께 준다: "앱에서 이 항목을 클릭 → 메모칸에 붙여넣기 → 저장 버튼."

## 하지 말아야 할 것

- Firestore 데이터베이스에 직접 쓰지 않는다. 서비스 계정 키 발급이나 원격 DB 쓰기 자동화는
  이 개인 학습 앱 규모에 비해 과한 구성이며, 대표가 최종 확인 후 손으로 저장하는 편이
  더 안전하고 명확하다.
- `js/data.js`의 항목 목록(title, id, 구조)을 임의로 수정하지 않는다 — 이 스킬은 설명 텍스트를
  "생성"하는 것이지 앱 데이터 구조를 바꾸는 게 아니다.
- 초안을 대표 확인 없이 바로 "완료"로 제시하지 않는다.
